# 伏声录制 · 棚内底噪归因

为伏声录制的临街棚归档配对声测，用可复算的偏相关确定隔音复测顺序。

## 现场与工作流

伏声录制是一支模拟的 8 人录音团队，承接播客和广告旁白。A 棚临街，空调风机和窗外交通在开棚高峰同时变响。录音助理原先从录音工程里挑 60 秒无声片段，将声级、手工车流计数、风机设置分记在工程备注和表格中。交班时文件和表格容易配错分钟。直接用全表相关会混入工作时带差异。安排复测后也难以追溯当时纳入了哪些记录。

上游输入是同一无声分钟的 A 计权等效声级 LAeq、车辆数、风机档位与测点。分析员先复核时段与声测编号，随后锁定输入运行诊断。业务负责人将证据转成隔音复测清单，观察员可下载发给录音及设施同事。

| 角色 | 页面 | 权限与典型动作 |
| --- | --- | --- |
| 声测分析员 `analyst` | 测量日历、声测记录、变量版本、底噪诊断、复测清单、改造验收 | 登记时段和声测、新建变量版本、发起诊断、提交改造验收、复核并导出计算证据 |
| 业务负责人 `admin` | 全部页面 | 执行分析员操作、复核完成的诊断、填写复测安排并发布、签发验收结论 |
| 观察员 `viewer` | 全部页面的可阅部分 | 查看时段、声测、变量版本与已发布诊断和验收，导出发布清单 |

## 一天的复测准备

1. 07:40，助理调出 11 月 9 日 `FS-1109-A` 的晨间校准记录，再核对 `FS-1112-A`、两次日班和两次晚间记录。样本库共 6 个时段、72 条声测。
2. 07:50，以分析员登录，在测量日历登记 `FS-QA-1121`，备注 `qa-roomtone-0750.wav`，工作时带设为清晨。
3. 07:51，关联录入 `FS-QA-001`。风机低档、录音位、车流 11 辆／分钟、LAeq 27.35 dB(A)。在声测记录里复核同一行的来源与数值。
4. 09:30，新建 `TRF-QA-02`，解释量用同步车流，控制工作时带、风机档位和测点。系统保留方案版本供复算。种子版 `TRF-01` 已提供相同控制组。
5. 09:35，在底噪诊断勾选七个时段，提交 73 条配对样本。查看原始及残差散点、相关系数、矩阵秩、自由度、快照指纹。验收样本的相关系数从 0.838675 降至 0.196032。
6. 09:45，对六个种子时段运行 `RANK-01`。工作时带嵌套于具体录音时段，结果保留原始系数，矩阵秩为 6／8，界面提示移除重复控制量。
7. 10:00，负责人复核可用诊断，发布 11 月 24 日 07:40 的复测安排。隔声门与临街墙各测两次 60 秒 LAeq，风机固定低档，同步登记车流。
8. 10:05，观察员打开已发布清单，并下载包含签核结论、输入快照、解释量设置、散点和系数的 JSON。后续增记现场读数时，已发布快照仍可复算。

## 改造验收的一天

1. 11 月 16 日，A 棚完成临街墙与隔声门的隔音改造。17 日和 19 日，助理按复测安排各测三个时段：`FS-1117-A/B/C`、`FS-1119-A/B/C`，并补录了隔声门测点；高档风机下临街测点改在路口旁同步计数。
2. 11 月 20 日 09:10，分析员在改造验收页提交 `ACC-1120`：改造前勾选 11 月 9 日与 12 日共 6 个时段，改造后勾选 17 日与 19 日共 6 个时段。同一时段不能算进两期，勾选时另一侧会自动禁用。提交瞬间如有同事补录声测，两期仍按同一时点同事务取数。
3. 09:11，计算完成。页面顶部显示降噪幅度：归一后等效声级由 36.81 dB(A) 降至 33.02 dB(A)，下降 3.79 dB(A)，覆盖 5／9 个风机×测点组合。
4. 分组表里，隔声门组合只有改造后测量，高档×临街两期车流范围不重叠，都标为不可比；逐条对账列出 180 条读数：纳入 85 条，排除 95 条，排除原因逐条可查（车流超出重叠范围、同车流档缺另一期样本、组合仅单期测量、两期车流不重叠）。
5. 09:20，负责人复核后发布验收结论。观察员可查看并下载含输入快照、分组权重、逐条对账的 JSON，凭样本指纹复算。

## 计算口径

- Worker 读取提交时选中的时段、该时段已录入的配对样本及方案版本，按记录 ID 排序并冻结至 MySQL JSON。规范化 UTF-8 JSON 的 SHA-256 指纹与诊断单一同保存，worker 取单时校验。
- 结果量 `y` 是 60 秒 LAeq。解释量 `x` 可选同分钟的车辆数，或风机有序档位 0／1／2。控制设计矩阵 `C` 含截距，按观测到的类别水平为每个控制量展开 `k−1` 列虚拟变量。
- Python 用 `numpy.linalg.lstsq` 同时估计 `βx`、`βy`，再计算 `u = x − Cβx`、`v = y − Cβy`。分别报告 Pearson `r(x,y)` 与 `r(u,v)`，其中 `r(a,b) = Σ(a−ā)(b−b̄) / sqrt(Σ(a−ā)² Σ(b−b̄)²)`。报告实际矩阵秩、列数、残差自由度 `n − rank(C) − 1` 和绝对相关变化。
- 配对少于 4 条、控制矩阵秩亏、控制量无变化、自由度不足 2 或残差近似恒定时进入阻断状态。矩阵秩和最小二乘拟合使用同一数值阈值。阻断结果保留原始系数（可定义时）和错误提示，发布入口只接受完成结果。
- `TRF-01` 校正时带、风机和测点，`AIR-01` 用风机档位为解释量并校正时带、测点，`RANK-01` 用共线控制组合验证阻断。同组种子保留两个日期，三种风机档位、两个测点和每种组合的两次读数。样本为确定性合成数据，重复 seed 依据自然键保留已有值。
- 改造验收 `traffic-standardized-laeq-v1`：提交时两批时段（前、后各一期）在同一事务内取数并冻结快照，补录与验收可同时提交而互不影响。样本按风机档位×测点分组，每组先取两期车流范围的重叠区间 `[max(两期最小值), min(两期最大值)]`，区间外读数排除；车流按 5 辆/分钟分档，只保留两期都有样本的档。每档内两期各算能量等效声级 `10·log10(mean(10^(L/10)))`，再按两期合并的档样本数为权重，把两期分别归一到同一车流分布后能量合成，组差即该组降噪量；各组按可比样本数加权合成总降噪幅度。
- 读数级排除原因：`GROUP_SINGLE_PHASE` 组合仅单期测量、`NO_TRAFFIC_OVERLAP` 两期车流范围不重叠、`OUTSIDE_TRAFFIC_OVERLAP` 车流超出重叠区间、`BIN_MISSING_COUNTERPART` 同车流档缺另一期样本。组级另标 `NO_COMPARABLE_BIN` 无共有车流档、`NARROW_TRAFFIC_OVERLAP` 重叠区间不足全范围一半。两期合计少于 4 条（`TOO_FEW_ROWS`）、任一期为 0 条（`EMPTY_PHASE`）或没有任何可比组合（`NO_COMPARABLE_GROUP`）时验收阻断，阻断结果仍保留逐条对账。

样本相关用于排复测，因果结论还需要现场干预与控制。演示以配对标量作为输入，录音文件名作为备注保留，声级仪负责生成 LAeq。每次诊断最多选择 100 个时段及 4,000 条声测，列表显示最近 4,000 条。验收两期合计同样以 4,000 条为限。观察员的可见范围以发布状态控制，同一演示实例共用目录。

## 启动和开发

```bash
cp .env.example .env
# 通过本批统一脚本进行 Docker 验收时，它会负责启动、重复 seed 和清理。
docker compose up --build --wait
docker compose exec -T backend python -m scripts.seed_demo
```

- 工作台 `http://127.0.0.1:18271`，API `/docs` 和 `/health` 位于 `http://127.0.0.1:19271`，MySQL 对本机开放 `127.0.0.1:17771`。
- `analyst@demo.local`、`admin@demo.local`、`viewer@demo.local` 的演示密码为 `Tape2026!`。前端登录页可以填入演示账号。
- 本地开发可使用 Compose 保持 MySQL 和 Redis 依赖齐备。修改 Python 后执行 `docker compose build backend worker`，修改页面后执行 `docker compose build frontend`，再用 `docker compose up --wait` 启动新镜像。容器内运行 `uvicorn src.main:app --host 0.0.0.0 --port 8000` 和 `python -m src.worker`。从前端入口调试 API 时由 Nginx 转发 `/api/`。
- `FRONTEND_PORT`、`BACKEND_PORT`、`DB_PORT` 调整宿主机端口。`MYSQL_DATABASE`、`MYSQL_USER`、`MYSQL_PASSWORD`、`MYSQL_ROOT_PASSWORD` 供首次建库及容器连接。`JWT_SECRET` 用于签发 8 小时令牌。`SEED_DEMO=true` 在后端启动时填充种子，本地手工 seed 亦可重复运行。开发配置中的账号和密钥需在部署前另行配置。
- Compose 默认网络使用独立的 `10.221.202.0/24`，可用 `NETWORK_SUBNET` 指定本机未占用的 CIDR。
- `mysql-data` 持久化项目记录，`redis-data` 持久化 Redis，`exports` 为 API 与 worker 共享的计算文件目录。验收环境由共享脚本调用 `docker compose down -v --remove-orphans` 清理。

| 层 | 组件 |
| --- | --- |
| 浏览器 | 原生 HTML、CSS、JavaScript，Canvas 绘制原始和残差散点 |
| API | Python 3.11、FastAPI、PyMySQL、JWT、审计、异常处理与请求 ID |
| 后台 | MySQL 行锁领取任务，NumPy 最小二乘，Redis 过期心跳 |
| 入口与存储 | Nginx 1.27、MySQL 8.0、Redis 7 |

`frontend/src` 按 API、store、组件、路由、页面、工具分层。`backend/src` 包含路由、输入 schema、查询模型、业务服务、worker 和中间件。`backend/migrations/001_studio.sql` 初始化库表，`002_acceptance.sql` 增加验收单；已有数据卷需 `docker compose down -v` 重建或手工执行该文件。`backend/scripts/seed_demo.py` 维护演示数据（生成逻辑在 `scripts/demo_data.py`，含 11 月 17／19 日改造后时段）。验收脚本、截图与记录位于同批 `test-artifacts/gb-5202`。

两端枚举定义在 `backend/src/constants/labels.py` 和 `frontend/src/constants/labels.js`。角色出现在账户表、接口授权与顶栏。时带出现在时段和散点图例。HVAC、测点出现在测量和模型设置。解释量、控制量出现在变量版本、快照和诊断详情。诊断阶段由 MySQL `diagnostics.state`、计算服务、worker 与前端 `phase` 共同使用。阻断码由计算服务和前端 `warnings` 使用。验收期别、读数排除原因与组标记由计算服务和前端 `acceptPhase`、`exclusion`、`groupFlag` 共同使用，验收单生命周期与诊断单一致。
